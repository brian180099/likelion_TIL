# 📘 Today I Learned

### 1. 오늘 배운 내용
- JavaScript와 JSX로 작성하던 React 프로젝트를 TypeScript와 TSX 기반으로 바꾸는 방법을 배웠다.
- 컴포넌트 props에 `interface`를 정의하면 어떤 값을 전달해야 하는지 코드 작성 단계에서 바로 확인할 수 있다는 것을 알게 되었다.
- `useState`에 제네릭을 사용해서 배열, 객체, 문자열 같은 상태의 타입을 명확하게 지정했다.
- `onChange`, `onSubmit`, `onKeyDown` 같은 이벤트 핸들러에 React 이벤트 타입을 적용했다.
- API 응답 데이터 구조를 타입으로 정의하고, 외부 데이터를 화면에서 사용할 수 있는 형태로 변환했다.
- React Router를 TypeScript 환경에서 사용하면서 목록 페이지, 상세 페이지, URL 쿼리 파라미터를 유지했다.

### 2. 핵심 정리 (내 언어로)
- TypeScript는 코드를 실행하기 전에 실수를 먼저 알려주는 도구라고 느꼈다.
- JavaScript에서는 props 이름을 잘못 쓰거나 없는 값을 사용해도 실행 전까지 모를 수 있는데, TypeScript에서는 타입 오류로 바로 확인할 수 있었다.
- 아기 사자 데이터처럼 여러 컴포넌트에서 함께 사용하는 데이터는 `src/types/lion.ts`에 따로 타입을 분리해두면 구조를 다시 확인하기 쉽다.
- 폼 상태, 필터 옵션, API 응답처럼 모양이 정해진 데이터에 타입을 붙이면 코드의 의도가 더 분명해진다.
- 처음에는 타입을 적는 과정이 번거롭지만, 나중에 리팩토링하거나 협업할 때 더 안전하게 코드를 고칠 수 있다는 장점이 있다.

### 4. 느낀 점
- 이번 과제를 하면서 TypeScript를 쓰는 이유가 단순히 문법을 더 배우는 것이 아니라, 실수를 줄이고 코드를 더 믿을 수 있게 만드는 것이라는 점을 알게 되었다.
- 특히 컴포넌트 props와 폼 이벤트에 타입을 붙이니 어떤 값이 어디로 흘러가는지 더 잘 보였다.
- 아직 타입 이름을 정하고 파일을 나누는 것은 익숙하지 않지만, 프로젝트가 커질수록 타입 정의가 코드의 설명서처럼 쓰일 수 있다는 생각이 들었다.
- 앞으로 React 프로젝트를 만들 때 처음부터 데이터 구조와 상태 타입을 같이 생각하면서 작성해야겠다고 느꼈다.

### 실행 및 검증
```bash
yarn install
yarn dev
yarn build
```

- `yarn build` 실행 시 `tsc -b` 타입 검사가 함께 실행되도록 설정했다.
- 모든 컴포넌트 파일은 `.tsx`, 데이터/훅/유틸 파일은 `.ts` 확장자를 사용했다.
