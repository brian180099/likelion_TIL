# 📘 Today I Learned

### 1. 오늘 배운 내용
- 로컬에서 실행하던 React 앱을 실제 배포 가능한 형태로 점검하는 과정을 배웠다.
- `yarn dev`는 개발 중 확인용 서버이고, `yarn build`는 배포용 파일을 만드는 명령이라는 차이를 알게 되었다.
- Vercel은 GitHub 저장소와 연결해서 main 브랜치에 push될 때 자동으로 배포해 주는 서비스라는 점을 정리했다.
- Supabase URL과 anon key 같은 값은 코드에 직접 넣지 않고 환경 변수로 관리해야 한다는 것을 배웠다.
- 배포 전에는 빌드 오류, 콘솔 로그, 반응형 화면, 로딩/에러/빈 상태를 확인해야 한다.

### 2. 핵심 정리 (내 언어로)
- 개발 서버는 내 컴퓨터에서만 확인하는 임시 실행 환경이고, 배포는 다른 사람도 접속할 수 있게 인터넷에 올리는 과정이다.
- Vercel을 사용하면 서버를 직접 관리하지 않아도 GitHub 코드 기준으로 자동 배포가 가능하다.
- 환경 변수는 민감한 값을 숨기면서도 앱이 Supabase와 연결될 수 있게 해주는 설정이다.
- 실제 서비스처럼 보이려면 기능뿐만 아니라 오류 안내, 빈 화면 안내, 모바일 화면까지 점검해야 한다.

### 4. 느낀 점
- 지금까지 만든 아기사자 대시보드를 단순한 과제 코드가 아니라 실제 서비스처럼 점검해 보는 과정이 의미 있었다.
- 배포를 준비하면서 코드가 잘 돌아가는 것과 사용자가 편하게 사용할 수 있는 것은 다르다는 걸 느꼈다.
- 앞으로 프로젝트를 만들 때도 마지막에 빌드, 환경 변수, 반응형, 에러 상태를 꼭 확인해야겠다고 생각했다.
